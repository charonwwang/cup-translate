# Qwen 朗读内容错配回修

日期：2026-10-26，Asia/Shanghai。用户反馈点击结果卡原文 `performance`，却听到无关的中文长文。这次验收检查音频内容，不再仅检查 WAV 格式、非静音波形或前端进入播放状态。

## 复现与定位

本机已有 0.6B CustomVoice、Vivian，安装元数据记录设备为 MPS。两个权重文件重新计算 SHA-256 均与固定 manifest 一致，未发现下载损坏，无需重新下载。

隔离调用同一模型，输入明确为 `text=performance, language=English`。MPS/float32 路径在一次生成中输出了 11.52 秒音频，离线 Whisper base 转写为完全无关的中文长句，复现用户现象。另一次英文整句 `Hello, this is a speech test.` 也被合成为中文，说明即使请求文本和语言正确，已有运行路径仍可能产出内容错误的有效音频。

同一权重改用 CPU/float32，并限制四个线程后：

| 输入 | 本地转写 | 实测生成耗时 |
| --- | --- | --- |
| performance | Performance | 4.38 秒 |
| Hello, this is a speech test. | Hello! This is a speech test. | 3.96 秒 |
| 表现和成绩。 | 表現和成績。 | 2.62 秒 |

纯生成参数调整不足以解决 MPS 路径：贪心、降低温度、改变文本预填方式仍出现异常或错误内容。因此未把实验参数作为根因修复。MPS/bfloat16 对照尚不足以覆盖长期及多语言稳定性，不直接替换默认交付路径。本轮 Mac 使用 CPU 兼容模式，CUDA 路径保留。

此外，结果卡原文与例句的 `useSpeech` 原先用固定 key，与当前文本无关。切换输入后旧请求仍可能迟到播放，这是独立的已确认生命周期缺陷。

## 实现

- Mac 自动选择 CPU；已有 `device=mps` 安装登记在启动时自动使用 CPU，并更新实际设备元数据，不改服务配置或重新下载权重。CPU 线程数限制在 1–4。
- 英文单词补终止标点，使用确定性生成与按长度计算的 token 上限。达到异常时长边界的音频拒绝播放、拒绝缓存。句子仍使用模型标准生成方式，不拼接试音或模板内容。
- worker 回复绑定请求编号、原文 SHA-256、语言及音色。Rust 逐项检查，不匹配即丢弃并结束该 worker。缓存命中仍返回本次请求身份；不记录用户原文或上传音频。
- 结果卡原文、例句和译文播放会话随输入、语言、服务、请求版本和隐私状态切换失效。原文输入区的朗读也加入自动检测语言和实际服务身份，并修正设备内模式误排除 Qwen 的问题。
- 模型管理器在 CPU 下说明兼容模式及资源控制。

## 验证

- Node：582 项通过；覆盖真实结果卡的三类音频身份随文本切换变化，以及旧请求迟到不能启动播放。
- Rust：199 通过、6 按原标记忽略；覆盖请求编号、文本摘要、语言、音色任一不匹配即拒绝音频。
- Python：8 项通过；覆盖旧 MPS 登记迁移、CPU 线程限制、单词生成参数及失控拒绝、请求与跨语言缓存绑定。
- CPU 单词对照：performance、dictionary、apple 的标准/确定性生成均被离线转写为对应英文单词；中英完整句子另行核对。保留原始转写结果，不把所有自动转写结果包装为逐字正确：短音频的自动识别仍可能出现误识别或同音字。
- 私有 worker 连续执行英文、中文、相同英文，校验三个请求身份和摘要；前后英文音频完全相同，中文音频不同，缓存不串语言。使用临时安装登记验证旧 MPS 元数据更新为 CPU。

转写仅用于此次本地测试，使用临时目录内的官方 `openai/whisper-base`，测试音频不上传，不引入产品依赖或额外打包模型。自动转写是内容核查证据，不是对所有未来生成的正确性保证。

## 安装与原生验收

已将 `efb2ab7` 构建为 ARM64 optimized release 并替换 `/Applications/cup-translate.app`，本地签名和签名后可执行文件摘要校验通过，版本号仍为 3.0.13。旧应用、配置和固定测试音频保存在私有目录 `~/Library/Application Support/cup-translate-local-backups/20261026-172933-efb2ab7/`。没有推送或公开发布。

原生结果页打开 performance、展开 HY-MT1.5 卡，使用 Qwen3-TTS 朗读原文；安装登记实际迁移为 CPU，旧进程已退出。用户随后明确反馈“ok,听了下朗读没问题了”，内容级验收通过。验收为稳定窗口临时关闭了失焦自动关闭，结束后已恢复原有设置。模型、服务配置和插件保持原样，没有重新下载 TTS 模型。

最终私有 worker 按英文 → 中文 → 相同英文执行，前两次生成约 4.27 秒、2.04 秒，第三次缓存命中约 0.00044 秒；最终两个 WAV 分别转写为 Performance 与 表現成績。详细机器记录见 [内容级验证证据](integration-evidence/speech-content-followup.json)。
