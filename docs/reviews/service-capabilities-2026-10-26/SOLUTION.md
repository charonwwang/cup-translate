# 服务配置与词典能力方案设计

状态：拟实施。对应 2026-10-26 的 3.0.13 问题评审。下一修复版本先恢复可靠配置、错误反馈和插件兼容，再引入离线词典增强；具体发布版本号在实施时确定。

## 功能归属

| 模块 | 负责 | 不应承担 |
| --- | --- | --- |
| 翻译服务 | 输入语言、目标语言、译文、引擎结果及其来源 | 保证所有模型返回音标 |
| 词典补全 | 词条、释义、音标或拼音、例句、词典音频与来源 | 更改主译文、偷偷联网 |
| 语音服务 | 原文或译文朗读、音色、语言能力、播放与停止 | 生成权威词典音标 |
| 收藏服务 | 把用户选中的词条导出到 Anki 等目标 | 给翻译卡片补词典数据 |
| 模型与连接 | 模型安装、运行依赖、连接管理、服务就绪状态 | 以下载成功替代配置或执行成功 |
| 插件管理 | 插件包、配置、启用、能力声明及兼容验证 | 将外部网页当成已验证市场 |

生词本页和产品文案优先改为“收藏与导出”，内置项写为“Anki 连接”。如果未来提供 Cup 本地生词本，应另立存储、导出和复习需求，不混入本次连接修复。

## 统一配置与状态原则

区分资源状态（未安装、安装中、已安装、损坏）、连接状态（未知、检查中、可用、不可用）、配置状态（草稿、已保存）和启用状态。四者可以组合，例如模型已安装但服务未启用、Anki 配置已保存但应用未启动。

所有编辑使用草稿。显式保存才写配置；普通关闭、取消、Esc 和遮罩关闭均丢弃本次未保存编辑。模型安装是独立后台任务，关闭编辑界面不会自动取消安装，也不隐式启用服务。若有未保存更改，界面内给出“放弃更改 / 继续编辑”，不得自动保存。

配置存储失败时保留草稿并提示重试，不添加服务列表项。保存涉及多字段时集中在配置仓储层提交；持久化完成后再更新列表和广播变更。无法真正原子写入时使用单一配置对象或可恢复提交标记，避免配置、服务列表与启用策略分开成功。

## Qwen 与语音服务

### 单一弹窗与入口

让 `QwenSpeech` 保留模型管理弹窗所有权；服务设置遇到 Qwen 时直接返回该组件，不创建外层 ConfigModal。或者抽出纯内容组件供单个壳复用；第一阶段选前者，后续按 Piper、Kokoro 的相同需求决定是否统一抽象。

模型中心与语音服务页调用同一控制器，传入明确的 `mode` 和保存回调。模型中心“完成安装”只更新安装状态；“设为后备朗读”才更新 `speech_policy`。服务设置“保存并启用”完成配置和服务注册。不得把所有 `onSaved` 都解释成切换默认朗读。

### 单例与迁移

当前 Qwen 的配置键为 `qwen_tts`，实现也是全局配置。本轮维持单例：一个默认音色、一种活动规格，列表不提供重复添加。迁移时把 `qwen_tts@...` 合并为规范键 `qwen_tts`，保留原顺序中第一处位置和现有全局配置；不删除模型文件。若没有全局配置，标记“待配置”，不凭旧列表项猜测已可用。

迁移须清点服务列表、首选服务、历史记录等引用。历史展示可保留旧 key，并通过只读别名解析；未明确映射的字段不批量字符串替换。以后若允许多实例，应再设计每实例配置与共享模型资源，不能只放开“添加”按钮。

### 安装与试听

安装保留“选择 → 检查 → 安装”。已安装标记沿用后端实际合成校验；界面显示“已安装，上次校验通过”，当前启动失败另显示，不把历史成功当成本次健康状态。

试听状态依次为待机、加载、合成、播放、停止或失败。可复用 `useSpeech` 的播放所有权和取消代次；关闭后迟到的音频不能重新播放。底层推理无法取消时，至少取消播放并如实表示后台计算仍在结束。错误显示简短原因、重试和日志路径；详细堆栈放折叠区。首次加载给出耗时提示，禁止空白阻塞弹窗。

“释放内存”只停止推理进程；“移除服务”取消服务引用；“删除模型”才删除文件，三者按钮和后果分别说明。

### 朗读策略

保留当前已建立的语义：Google、Lingva 优先使用自身朗读，其余引擎使用所选后备服务。界面将全局选项明确命名为“后备朗读服务”，结果卡显示本次实际使用者。`off` 是全局禁用；若产品以后要“所有引擎强制使用某 TTS”，新增明确策略，不改变现有选项含义。

配置列表按顺序选择第一个支持当前语言且已就绪的实例；显式选择的单个服务不可用时提示“配置语音 / 重试 / 改用其他服务”，不隐式切换到联网服务。联网服务仍受统一隐私策略限制。

## Anki 连接与收藏

### 配置流程

页面先解释：“需要安装并打开 Anki 桌面版，在其中安装 AnkiConnect，重启 Anki 后测试连接”。默认主机固定本机，端口为 8765；高级项支持 API key，使用现有凭证存储能力，避免日志或导出配置泄露明文。

提供“测试连接”和“保存配置”两个动作。测试只请求 `version`，并按需只读获取 `deckNames`、`modelNames`、`modelFieldNames`；不得调用 `createDeck`、`createModel`、`addNote`。测试结果随端口或 API key 变化失效，异步旧响应不能把新草稿标成可用。

允许保存离线配置，标记“已保存，尚未连接”；连接测试成功标记“本次连接正常”。设置中预选 Cup 默认牌组与卡片模板，实际创建延后到用户第一次明确收藏。高级自定义牌组和字段映射列入 P2，首期不暴露未经验证的任意模型配置。

### 适配器与错误

抽出 `requestAnki(action, params, config)`，集中处理请求超时、HTTP 失败、JSON 结构、业务 `error` 与预期 `result` 类型。连接测试要求协议版本满足 v6 所需能力，不能把任意 HTTP 200 当作 AnkiConnect。

| 错误码 | 用户可见提示 | 恢复动作 |
| --- | --- | --- |
| ANKI_UNREACHABLE | 无法连接本机 Anki，请确认已启动并安装 AnkiConnect | 连接指南、重试 |
| ANKI_TIMEOUT | Anki 连接超时 | 重试、检查端口 |
| ANKI_AUTH | AnkiConnect 需要或拒绝了 API key | 修改密钥 |
| ANKI_PROTOCOL | 当前端口响应不符合 AnkiConnect 协议 | 检查端口、升级插件 |
| ANKI_MODEL | 牌组或卡片字段不匹配 | 检查配置 |
| ANKI_DUPLICATE | 该词条已存在 | 查看 Anki，不显示新增成功 |
| ANKI_WRITE_FAILED | Anki 未确认收藏成功 | 查看详情、重试 |

错误对象保留原始原因供诊断，界面默认最多三行并可展开复制。请求中密钥、完整卡片内容不进入默认日志。

### 实际收藏

用户点击收藏后才允许写入：确认连接 → 检查牌组和模型 → 缺失时创建 Cup 默认资源 → 校验字段 → `addNote` → 校验返回 note ID → 显示成功。不要每次无条件 `createModel`，已存在时先检查，不吞掉所有建模错误。

先把主译文及词典补全组装为标准收藏数据，HTML 转义用户文字，限制音频大小并使用稳定安全文件名；支持缺音标、缺音频、纯文本和结构化释义。保留已有音频过滤与分块编码能力。词典音频可以随卡片导出；TTS 音频生成默认不是收藏的必选步骤。

同一词条请求中禁用重复点击。若 `addNote` 超时，状态为“结果未确认”，不能直接自动重发；先按稳定标签或内容指纹查询 Anki，避免第一次已落盘却创建重复卡片。P1 首期可采用人工确认后重试，完整去重查询作为后续增强。

## 插件兼容与分发

### 近期方案选择

复用 Pot 的包格式和已有生态，建立 Cup 的兼容验证清单。首次交付用仓库 `docs/plugins/` 和应用内说明即可，不需要先建独立网站。Pot 链接标注“Pot 社区插件目录，兼容性未经逐项验证”；优先入口指向 Cup 自有说明。

静态清单记录插件 ID、类别、来源、版本或 commit、包 SHA256、平台、所需凭证或运行时、网络行为、测试日期、Cup 版本及安装和执行结果。状态使用“已验证 / 有条件支持 / 未验证 / 不兼容”，不能继承上游 official 标签作为 Cup 背书。下载失效和服务失效需要独立状态。

有稳定兼容插件和维护需求后再用 GitHub Pages 等静态托管展示同一清单；域名和网站不是加载器的前置依赖。本轮不引入市场账号、自动更新或远程执行。

### 包与路径规则

保留现有无点号 ID 的兼容，同时允许合法点分 ID。按安全的单路径分量解析：限制长度；拒绝空字符串、控制字符、路径分隔符、盘符、前后空格、`.` 与 `..` 段；点分段不得为空。既有 `plugin...` 前缀兼容行为通过历史样本确认后再定，不仅凭三个上游样本收紧全部旧 ID。

前后端、安装、目录发现、服务键识别、加载、运行二进制使用同一契约；新增跨语言测试和真实上游 fixture。保留路径穿越、符号链接和特殊权限位防护；还需明确拒绝 Windows 保留设备名或非法尾随字符，最终落盘路径必须处于插件根目录。

安装包 stem 与 `info.id` 一致；旧的重命名包使用显式迁移映射处理，不能未经确认直接改 ID 导致配置丢失。检查类别、入口函数、必填元信息、语言映射与图标路径。压缩包设置总解压大小、条目数量和单文件限制。先在临时目录完整验证，成功后原子替换，保留可回滚旧版本；多包安装逐包返回状态，避免一个失败掩盖前面成功。

### 自定义与 npm

自定义插件按照类型实现 `translate`、`tts`、`recognize` 或 `collection`，暴露宿主约定函数并返回约定数据，以 `.potext` 安装。TTS 返回音频字节，翻译可返回文本或已验证的结构化词典结果；所有能力都要经过对应的适配测试。

当前通过 `eval` 执行脚本并注入 HTTP、文件读取、数据库、CryptoJS 和二进制运行工具，没有 Node 模块解析和 npm 安装入口。不能在应用内直接 `npm install` 然后使用。开发者可以在构建阶段使用 npm 管理依赖并打包为宿主可执行的单脚本；依赖 Node 原生 API、原生模块或外部二进制时需要专门适配。

插件目前不构成隔离沙箱。安装前展示来源、类别和能力说明，只安装可信包；不要把将来的“权限声明”写成现有运行时已强制限制。隐私模式尤其要验证插件自身网络和二进制调用能否受控，无法强制执行设备内限制的插件在该模式中禁用，而不能只在入口做一次策略检查就宣称不会联网。

## 词典补全与文字分类

### 显示规则

源词条文字始终可朗读，只要选定 TTS 支持对应语言；音标缺失不隐藏朗读。标题按钮名为“朗读原文”，译文按钮名为“朗读译文”，音色与实际服务在结果卡可查看。

源文字先按语言和文本形态判定：英语单词可以进入词典视图；中文无空格短语不依据“无空格”直接认定单词。中日韩文本没有可靠分词或词典命中时使用“词语 / 文本”，不显示英语 IPA 缺失告警。中文拼音只有在来源可信时展示；句子不默认展示音标缺失占位。

英语单词无音标时显示轻量“暂无词典音标”，另提供“查询词典信息”。中文短语不显示该提示；可提供明确的“查询词语释义”。不把 HY-MT 模型生成内容标记为权威词典。

### 数据契约

设计新增独立 `DictionaryEntry`，包含 `query`、`language`、`normalizedKey`、`pronunciations[{notation, region, symbol, audioRef, source}]`、`senses`、`examples`、`source`、`license`、`generated`、`fetchedAt`。`notation` 区分 IPA 与拼音；音频地址和字节使用不同类型，不靠字符串真假判断。缺字段用空数组或缺省值，不能编造。

补全状态独立于主翻译：未查询、查询中、有结果、无词条、失败、隐私阻止。结果绑定请求代次、原文与语言；输入变化中止旧任务，迟到结果不能污染新卡片。补全只能增加缺失词典字段，不覆盖用户当前引擎的成功译文，并分别标出数据来源。

缓存键包含规范化词条、语言、词典提供者和数据版本；建议在线命中缓存 30 天、无结果缓存 1 天，作为可调整默认值。设备内模式不得读取不明来源的远程音频地址并请求网络；允许使用已落盘且来源清楚的本地数据。

### 分期实现

P1 先修分类与文案，并保持现有手动在线补全及隐私拦截。P2 再抽出词典提供者接口，接入独立离线英汉词典。ECDICT 可作为候选，需校验具体数据版本、覆盖范围、许可证、分发与文件摘要；它不提供全语种音标，也不等于自带朗读音频。TTS 仍独立供给。

在线补全仅在允许联网且用户选择后进行；显示会发送原文及目标服务。纯离线场景无词典时，返回“当前未安装适用词典”及可选安装入口，保留翻译和本地 TTS。新增离线包通过现有模型资源管理能力下载、校验、取消和删除，不另造一套安装状态。

## 文档与兼容性决策

以产品交互规范定义模块责任，以本方案定义此次技术演进；历史研究报告保留日期和实测范围。`docs/MAINTENANCE.md` 中“默认功能、平台优先级”等较早定位与现有实现不同，不能直接当作当前验收标准；应在本轮实施完成时逐条核对后更新，避免一边实现、一边仍由旧文档驱动删除能力。

本轮不实施 npm 市场、完整本地生词复习系统、所有语言离线词典或强制统一 TTS。新增需求需要单独定义用户路径、能力和数据迁移。
