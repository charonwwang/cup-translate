## 1. 为什么要改

问题不在配色，而在**信息架构与交互逻辑本身过时**。现状实测（读码得出，非主观印象）：

### 1.1 设置窗口

| 现象 | 代码位置 | 影响 |
|---|---|---|
| 侧栏 = 230px 宽的 logo + 8 个「平铺大按钮」 | `src/window/Config/index.jsx:32`、`components/SideBar/index.jsx` | 侧栏占掉 1/4 宽度只为放 8 个词；60×60 的 logo 与「设置」这个场景无关 |
| 每页再叠多张 `Card`，卡片内每项只有 `margin:10px 0` | `Config/style.css`（全文件 4 行） | 没有分组层级、没有行分隔，设置项一多就糊成一片 |
| 设置项一律 `h3 + 控件` 左右对撒 | 各 `pages/*/index.jsx` | 控件垂直中线不统一（`Switch` 与 `h3` 不同高，部分页面靠 `my-auto` 手调） |
| 更新提示、版本号、导航挤在同一列 | `SideBar` + `index.jsx` | 侧栏同时承担导航与信息展示两种职责 |
| 无搜索 | — | 分区已有 8 个，找一项设置要靠记忆 |

### 1.2 翻译弹窗

| 现象 | 代码位置 | 影响 |
|---|---|---|
| 源文卡片 → 语言条 → **每个引擎一张卡片**垂直堆叠 | `Translate/index.jsx:278-338` | 引擎 4 个以上就必须滚很长；源文与译文之间被语言条切断 |
| 语言交换按钮被夹在源/目标语言中间，居中还是靠 `CardFooter` 三列 | `LanguageArea/index.jsx:46-125` | 交换是「语言条」的操作却占着正中间，视觉重心错位 |
| 置顶 / 关闭是两个孤立图标按钮，与语言、引擎无关联 | `Translate/index.jsx:242-274` | 窗口级操作散落在内容区顶部 |
| 未配置的引擎仍会展开卡片 | `required_config.js` 只做跳过 | 用户看到一张空卡片 + 「未配置」，信息密度低 |
| 拖拽手柄 = 整张卡片 | `TargetArea` `{...provided.dragHandleProps}` | 卡片内任何拖动都会触发排序，与选中文本冲突 |

## 2. 设计原则（v2）

1. **安静优先**：非聚焦元素默认降低对比（操作图标 hover 才出现、次级文字用 `--fg-3`），界面在用户需要它之前不抢注意力。
2. **一屏一事**：翻译弹窗只有一个输入焦点（源文），其余全部只读。
3. **层级用空间，不用边框**：靠间距、圆角、背景层差（surface / surface-2）区分层级，边框仅用于需要明确边界的地方（当前用的 `border-1` 到处描边是「老旧感」的主要来源）。
4. **状态即位置**：窗口级操作进标题栏，区块级操作在区块头，条目级操作 hover 出现——不再把所有按钮平铺。
5. **令牌驱动**：颜色/圆角/阴影/间距全部走 CSS 变量，浅深主题只换变量，不换结构。

### 2.1 视觉语言

- **强调色**：暖橙 `--brand-500 #f2801f`。理由：图标母版（`app-icon.png`）已是暖橙→焦糖渐变 + 咖啡杯，UI 主色与图标同源，比现状的青色 `#49cee9`（与图标毫无关系）更成体系。
- **中性色**：暖灰（`#231f1b` / `#f7f6f4`），与橙色同调；现状的 `#202020` 是冷灰，与橙色图标并置会「脏」。
- **圆角**：6 / 8 / 12 / 16 / 22 五档，按「控件 < 卡片 < 弹窗」递进；现状所有元素一律 `10px`，缺层次。
- **阴影**：三档，仅卡片与浮层使用；现状的 NextUI `shadow='none'` 与默认阴影混用，同一界面里两种卡片质感。
- **字号**：13.5/14 正文、11.5/12 辅助、22 页面标题；现状正文 16px 起，设置页一屏放不下几项。

## 3. 设置窗口重构

**旧**：logo + 8 个平铺按钮的侧栏 → 多张 Card → `h3 | 控件` 行
**新**：紧凑导航列表（图标 + 标签 + 快捷键数字 + 搜索 + 版本/更新位）→ 内容区「大标题 + 副标题」→ 分组卡片 → 行式设置项（左标题/说明，右控件，行间细线）

逐项对应：

| 旧 | 新 |
|---|---|
| 8 个 `Button size='lg' variant={flat/light}` | `.nav-item`：图标 + 标签 + 右侧数字键提示，选中态为白底 + 阴影 + 图标着橙 |
| 60×60 logo 居中 | 26×26 微标 + 产品名 + 一句话定位（`Side-brand`） |
| 无 | 侧栏搜索框（跨分区搜设置项，后续用 `config.*` 的 i18n key 建立索引） |
| 更新提示无入口 | 侧栏底部 `.update` 行（发现新版本才出现）+ 版本号 |
| 标题栏仅标题 + 右侧窗口控制 | 保留，但控制按钮改为 44×44 命中区，关闭按钮 hover 变红 |
| `Card` + `CardBody` 无标题 | `.card` 带 `.card-head`（标题 + 右侧提示），分组语义明确 |
| `config-item`（4 行 CSS） | `.field`：`min-height:52px`、左说明右控件、`border-top` 分隔、``.desc` 次级说明 |
| `Switch` / `Input variant='bordered'` / `Dropdown` 混用 | 统一控件族：`.switch`、`.input`、`.select`、`.segmented`（2–3 选项时用分段控件替代下拉，少一次点击） |
| 快捷键用 `Input` 裸展示 | `.recorder`：kbd 样式按键 + 录制态边框变橙 + 呼吸点；块级快捷键用纯 `.kbd` 展示 |
| 服务列表 = N 张卡片 | `.svc` 行：拖拽手柄（hover 出现）+ 首字母头像 + 名称/说明 + 徽标 + hover 操作 + 开关 |
| 历史 = `Table` + 分页器分散 | 工具栏（搜索/筛选/导出/清空）+ 表格 + 底部翻页合一卡 |

**新增的能力**（原型已画，需后端配合的已标注）：

- 侧栏搜索：纯前端过滤，无需后端。
- 服务徽标：免费 / 本地 / 需密钥——需要服务元数据里补一个字段（可选，缺失时不显示）。
- 快捷键冲突提示：现有 `isRegistered` 已能查，只需加展示位。
- 备份页的状态行（上次备份时间/大小）：需要 `backup` 模块回传，属可选增强。

## 4. 翻译弹窗重构

**旧**：源文卡 → 语言条 → 每引擎一张卡
**新**：弹窗标题栏（状态 + 窗口操作）→ 源文块 → 语言条 → 结果卡（首位为主角）→ 底部固定操作条

| 旧 | 新 |
|---|---|
| 置顶/关闭在内容区顶部 | 移入 `.Pop-head`：左侧是状态徽标（`已翻译 · 142 ms`），右侧 4 个图标按钮（换引擎 / 设置 / 置顶 / 关闭），标题栏整体可拖拽 |
| `SourceArea` 卡片，头部含引擎选择 | `.Source`：语言标签 + `自动检测` 徽标 + 正文（唯一可编辑区）+ hover 工具栏 + 字符数 |
| 语言条是三列 `CardFooter` | `.Langbar` 单行：源语言下拉 · 圆形交换按钮 · 目标语言下拉 · 右侧「翻译」按钮（自动翻译模式下省略） |
| 每引擎一张等高卡片 | `.Result`：首位 `.hero`（橙描边 + 更大字号，即「主结果」），其余同级；未配置/失败**不展开空卡**，压成一行状态 + 重试按钮 |
| 拖拽手柄 = 整卡 | 手柄收进结果卡标题栏左侧（原型中按需展开），避免与选词冲突 |
| 无加载设计 | `.skel` 骨架屏按结果卡形状铺，不再是 `PulseLoader` 转圈 |
| 错误仅 toast | 卡片内 `.err-box` 常驻错误文案 + 卡片头「重试」 |
| 无底部操作条 | `.Pop-foot` 固定：朗读 / 复制译文 / 存生词本 + 右侧快捷键提示 |

**保留的既有配置**（一一对应，不新增设置项）：`translate_close_on_blur`、`translate_always_on_top`、`translate_window_position`、`translate_remember_window_size`、`hide_language`、`hide_source`、`incremental_translate`、`dynamic_translate`、`translate_delete_newline`。

## 5. 落地路径（评审通过后）

分三步，每步都可独立验证、独立回滚：

| 步骤 | 范围 | 验证 |
|---|---|---|
| **P1 令牌层** | 新增 `src/theme/tokens.css`；改写 `tailwind.config.cjs` 的 `nextui()` 色板（`background/content/primary/default`）对齐新令牌；`Config/style.css` 扩为组件样式 | `pnpm build` + GUI 目视：现有页面在新色板下的表现 |
| **P2 设置窗口** | 重写 `Config/index.jsx`、`components/SideBar`；新增 `components/{NavItem,Field,SettingCard,Segmented,Recorder,ServiceRow}`；各 `pages/*/index.jsx` 由 Card 改为 `SettingCard + Field` | 逐页对照原型；8 个分区全部走一遍 |
| **P3 翻译弹窗** | 重写 `Translate/index.jsx`、`components/{SourceArea,LanguageArea,TargetArea}`；保持 jotai atom 与 `useConfig` 的 key 不变 | 真实 X11 会话下划词、拖拽排序、失焦关闭、置顶 |

**约束（来自 CLAUDE.md，必须遵守）**：

- 前端是 **JSX 不是 TS**，4 空格缩进 / 单引号 / 行宽 120 / JSX 属性每行一个（`.prettierrc.json`）。
- 改前端后必须 `pnpm build` 再 `cargo build --release --features custom-protocol`（`dist/` 会被嵌进二进制）。
- 不引入新的 UI 依赖；NextUI 若保留则只作为行为原语（Modal/Dropdown），视觉一律由令牌层接管。是否**移除** NextUI 单独立项评估（它带来的 `nextui()` 主题与我们的令牌重复）。
- 界面改动涉及品牌视觉时同步 `packaging/ICONS.md` 与 `CLAUDE.md` §3.1（本方案主色取自现有母版图标，不涉及图标改动）。

## 6. 已知取舍（请评审时明确）

1. **主色更改**（青 → 橙）：视觉冲击最大的一项改动。替代方案是保留青色、只改结构。
2. **是否保留 NextUI**：原型是纯 CSS 实现，说明**不用组件库也能达到该效果**；移除可减约 12 个依赖但工作量大，建议 P1–P3 完成后单独立项。
3. **弹窗宽度**：原型 460px（现状约 400px，随语言条浮动）。是否接受更宽一点，取决于目标屏幕。
4. **侧栏保留 vs 标题下拉**：原型两种都画了（设置窗口下方「方案对照」）。侧栏版信息密度高、可扩；下拉版省空间但隐藏分区全貌。**建议侧栏版**。
5. **动画**：原型只用了 150–250ms 的过渡，未做进出场动效（Tauri v1 + WebKitGTK 下大面积 backdrop-filter 与动效可能掉帧）。弹出动画建议后续单独验证。
