先说结论

不是三个词走了三套 UI，而是 Google 返回的词条字段并不齐。

同一请求里，词典释义在 result[1]，例句在 result[13]。 三个字段是否出现，完全由上游决定。现在的界面直接把返回结果画出来，所以 query 没有例句、modality 没有词性、importance 只有一条例句。 新方案要求数据层先归一成完整词条，再交给统一组件呈现。

Review note

这版需要你确认的四点

这一轮只评审信息结构。颜色、圆角等视觉细节可以继续收紧； 真正决定后续实现量的是下面的展示规则。

  • 单词：结果里再次展示原文与音标，词性只做标签，所有释义保持同一字号。
  • 单词：默认给出两条例句；每条原句、译文都有独立朗读按钮。
  • 短语：结果区只保留译文；以表达和用法为主，替代译法同级展示。
  • 段落：默认整段译文；切到“对照”后才逐句显示原文与译文。
评审通过后的数据层约束 word, phonetics[], senses[{ pos, meanings[] }], examples[2]

Google 缺词性时补词典源，缺例句时补例句源或跨词条例句；译文缺失时再补一次目标语言翻译。 具体供应商不在本轮锁定。
