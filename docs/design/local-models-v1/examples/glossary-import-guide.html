Glossary import spec · v1

把团队术语带进来，
不需要改代码。

首发计划支持本地 CSV、JSON 导入；TMX 与 HTTPS 定时同步列入后续。 第一次使用建议从 CSV 开始；需要保留完整字段时使用 JSON。TMX 翻译记忆需后续单独适配。

下载 CSV 模板 适合 Excel / Numbers 编辑 下载 JSON 模板 适合脚本生成与链接同步 下载 TMX 模板 兼容常见 CAT 工具

快速开始

在“术语与风格”页面点击“导入术语库”，选择来源后先预览，再决定合并方式。导入不会直接覆盖当前术语库。

第一次使用：CSV

一行一个术语，首行是字段名。可以用 Excel 编辑，另存为 UTF-8 CSV。

需要自动更新：JSON + 链接

把 JSON 放在固定 HTTPS 地址，设置每天或每周检查一次。

已有翻译记忆：TMX

后续支持 TMX 1.4；导入时区分翻译记忆与术语候选，默认建议，不作为强制术语。

需要完整说明：JSON

可以保留标签、大小写规则、优先级和注释。

最小可用文件只需要两列：原文和译文。其他字段都是可选的；导入向导会自动补默认值。

CSV 格式

首行必须是字段名，逗号分隔。包含逗号、引号或换行的内容请使用双引号包裹。

列名 必填 说明
source 是 原文术语或短语
target 是 希望固定输出的译法
mode 否 suggest 建议（默认）；旧 locked 仅保留约束意图，首发显示不支持强制约束
case_sensitive 否 true / false，默认 false
priority 否 整数，越大越优先，默认 50
comment 否 给团队看的说明，不参与翻译 
source,target,mode,case_sensitive,priority,comment
worker threads,工作线程,suggest,false,100,"区别于“工人线”"
memory leak,内存泄漏,suggest,false,100,"团队统一使用“泄漏”"
shutdown,关闭,suggest,false,50,"按语境也可使用“停机”"
从 Excel 导出时选择“CSV UTF-8”。不要使用公式单元格；以 =、+、-、@ 开头的内容会按普通文本处理。

新版顶层 id 与 entries[].id 是稳定标识，编辑时不变。CSV 可省略 id 并在导入时生成；重复导入需预览确认。CSV 语言方向在向导中必选。首发限制、迁移与冲突规则以 v2 方案为准。

JSON 格式

JSON 适合动态生成与版本管理；链接同步不在首发范围。顶层是一个对象，entries 是术语数组。

{
  "schemaVersion": 2,
  "id": "tech-en-zh-cn",
  "name": "技术研发",
  "sourceLanguage": "en",
  "targetLanguage": "zh-CN",
  "description": "后端与基础架构术语",
  "entries": [
    {
      "id": "tech-001",
      "source": "worker threads",
      "target": "工作线程",
      "mode": "suggest",
      "caseSensitive": false,
      "priority": 100,
      "comment": "区别于“工人线”",
      "tags": ["backend", "runtime"]
    }
  ]
}
字段 类型 说明
schemaVersion number 新版为 2；兼容导入旧版 1，未知版本拒绝
sourceLanguage string ISO 语言代码，例如 en
targetLanguage string ISO 语言代码，例如 zh-CN
entries[].source string 原文，不能为空
entries[].target string 译文，不能为空
entries[].mode string 默认 suggest；旧 locked 仅保留意图并显示能力限制
entries[].tags string[] 可选，用于筛选与批量管理

TMX 格式（后续）

首发不提供 TMX 导入。后续设计拟支持 TMX 1.4 的 tu / tuv / seg。导入器只读取源语言和目标语言两个句段。

<?xml version="1.0" encoding="UTF-8"?>
<tmx version="1.4">
  <header srclang="en" />
  <body>
    <tu>
      <tuv xml:lang="en"><seg>worker threads</seg></tuv>
      <tuv xml:lang="zh-CN"><seg>工作线程</seg></tuv>
    </tu>
  </body>
</tmx>
后续 TMX 导入默认作为建议候选，优先级 50；整句翻译记忆不能默认变成强制术语。重复和冲突需要预览确认。

链接同步（后续）

链接同步读取一个返回 JSON 的 HTTPS 地址，适合团队共享术语库或由脚本生成术语表。

  • 只支持 HTTPS；URL 必须返回 application/json。
  • 文件结构与 JSON 导入完全一致，建议使用固定版本化地址。
  • 可以设置每天、每周、每次启动或仅手动检查。
  • 同步失败时保留上一次成功版本，并标记“已过期”，不会清空术语库。
  • 会读取 ETag / Last-Modified，未变化时不重复下载。
链接同步只会保存解析后的术语和文件摘要，不执行远端 JavaScript、HTML 或任意代码。

字段规则

规则 行为
大小写 caseSensitive: false 时英文默认忽略大小写
优先级 数值越大越优先；手动词条高于导入词条
最长匹配 worker threads 优先于 threads
强制模式 首发不支持强制；旧 locked 条目保留意图并显示能力限制，不能标记为已锁定
建议模式 模型未使用该译法时提示，不强行破坏句子
代码标识符 URL、邮箱和明确标记的代码区域跳过；普通文本中的变量名不能保证自动识别

冲突与合并

导入向导会先显示新增、更新、重复、需确认和格式错误的数量，再让你选择合并方式。

模式 行为
合并（推荐） 新增缺失词条；已有词条按导入内容更新
跳过重复 保留现有译法，只导入新词条
整体替换 清空当前术语库后导入，执行前需要二次确认
同一原文出现不同译文、空值、超长文本或与现有术语冲突时，会进入“需确认”，不会静默导入。

限制与安全

  • 单文件最大 10 MB，最多 50,000 条术语。
  • 只接受 UTF-8 编码；CSV 建议带 UTF-8 BOM 以兼容 Excel。
  • 导入文件在本机解析，不上传到 cup-translate 服务器。
  • 链接同步只读取 HTTPS，不执行远端代码，不跟随跨域重定向。
  • 导入前会备份上一版术语库；出现问题时可在“版本记录”中恢复。
