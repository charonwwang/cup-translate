## 1. 已确定的产品决策

- 新用户翻译服务默认仅 Google；不重置老用户服务、排序、名称或配置。
- 保留当前翻译窗口布局；不添加安装入口、模型管理条或大幅重做结果 UI。模型统一从设置添加。
- 保留多服务并行比较。服务排序控制展示顺序与主结果，不代表失败后逐个尝试。
- 原首发 OPUS-MT 中英模型保留；按 2026-10-21 用户追加要求接入 M2M-100 418M int8 多语种模型。另按追加要求接入 HY-MT1.5 1.8B、Piper 与 Kokoro；Hy-MT2、任意 HTTP 协议、云 TTS、TMX 和链接同步仍留待后续验证。
- 术语库首发承诺“识别、提示词偏好、输出校验”，不承诺任意引擎都能强制替换译文。
- 全局“仅在设备处理”是首发必备能力；本地服务不自动回退在线服务。
- 首发复用已有 OpenAI-compatible、Ollama 配置和调用，覆盖兼容的 LM Studio/vLLM；不另写一套重复服务体系。
- 安装结束是否启用由向导中的开关决定，默认开启；启用只代表加入服务，不能改变全局隐私模式。
- 模型版本锁定；更新需用户触发，不静默替换。TTS 默认配置不随本次迁移改变。

## 2. 范围与交互

### 2.1 首发范围

| 功能 | 首发行为 | 后续扩展 |
|---|---|---|
| 模型与连接 | 设置页统一入口，复用服务实例 | 更多本地模型和协议 |
| 本地翻译 | OPUS-MT、M2M-100、HY-MT1.5 1.8B Q4/Q8；先选系列再选规格 | Hy-MT2；新增平台与模型继续验证 |
| 本地语音 | 系统语音、Piper 独立音色包、Kokoro 多语共享包；试听、下载、卸载 | Windows SAPI 接入；更多语言与平台验证 |
| 自定义连接 | OpenAI-compatible、Ollama；连接测试和固定样例试译 | 任意 HTTP 返回映射、Azure/ElevenLabs/TTS 协议 |
| 术语 | 编辑、CSV/JSON 导入、匹配、提示词注入、输出校验 | 经过验证的硬约束、TMX、远程同步 |
| 隐私与凭证 | 请求级隐私过滤、系统凭证库、旧数据迁移、日志脱敏 | 显式回退链等高级策略 |

未验证的模型不提供可点击安装按钮；可隐藏或显示“尚未提供”，不能只贴 Beta 标签后照常安装。领域模板只给示例词条，不暗示医学、法律专业准确性。

### 2.2 安装向导

设置 → 模型与连接 → 添加本地模型 → 选择模型系列 → 选择规格或音色 → 设备与许可检查 → 安装。

- 展示实际语言方向、下载大小、平台支持、来源和许可。内存数据注明设备、方向、线程与测量条件，不把单机约 160 MB 当作双向或所有平台保证。
- 自动检查架构、运行时、可用磁盘、内存信息；无法读取内存时展示“无法估算”，不伪造适配结论。磁盘预留下载暂存与安装所需空间。
- 线程和解码模式自动设置，既有高级参数保留在高级设置中。
- 真实进度展示下载、校验、预热和启用；不使用定时器模拟成功。
- 双向包按方向独立记录可用性。单向完成时显示“部分安装”，完整向导成功需两个方向自检通过；已验证方向可由用户单独启用。
- 关闭向导可后台继续；退出应用时持久化任务，重启后显示可恢复任务，不隐式开启下载。
- 翻译窗口只呈现可调度结果；用户主动安装、暂停、重试、删除均在设置完成。

### 2.3 能力检查与错误显示

- 调度前过滤：禁用、未配置、未安装、语言方向不支持、被隐私策略排除的服务，不挂载执行组件、不发送请求。
- 设置页解释不可用原因。无可用服务时在结果区显示可操作的整体提示；“仅在设备处理”下不能偷偷启用 Google。
- 通过检查后加载失败、内存不足、推理失败，应保留该服务错误卡，支持重试和到设置处理。
- 支持语言对用有方向的集合表示，不从 `languages: ['en','zh']` 推断双向能力。

## 3. 调度与隐私契约

### 3.1 多结果执行

```text
输入和请求 ID
  → 读取隐私模式、服务配置与术语版本快照
  → 本地语言检测（仅设备模式强制本地；普通模式沿用检测偏好）
  → 筛选启用、已配置、就绪且支持方向的服务
  → 在资源限制内并行生成结果
  → 输出校验与结果呈现
  → 按用户偏好写历史 / 自动复制 / 朗读
```

- 排序与主结果身份按过滤后的有效列表计算，避免不可用第一项导致自动复制失效。
- 旧请求取消或失效后，不得更新卡片、写历史、复制或触发朗读。HTTP 传递取消信号；不能中断的本地推理至少保证结果作废且队列有界。
- 首发没有自动跨服务回退。未来回退链独立配置、有总时间和次数上限，同一输入不得无意重复计费。
- 原始结果和术语校验结果分开保存；流式内容显示为临时结果，结束后统一校验。历史、复制、朗读使用同一最终结果。

### 3.2 两个不同概念

| 概念 | 含义 |
|---|---|
| 本地服务不联网兜底 | 当前本地服务失败不会改调在线服务；其他启用的在线卡片在普通模式仍可请求 |
| 仅在设备处理 | 整次处理链不能把输入、译文、术语或衍生文本发送给远程服务 |

- 全局隐私过滤发生在语言检测、翻译、OCR、原文/译文 TTS、术语实时预览、连接测试和试译等每个文本请求入口之前。
- 受限模式下仅放行内嵌运行时和已验证的系统离线语音。普通插件、远程 HTTP、自定义代理默认不放行。
- `localhost` 不能证明推理离线：首发在严格模式下也阻止未受信的外部 HTTP 服务，即使地址是回环地址；普通模式仍支持连接。不能仅靠 `capabilities.localOnly=true` 自报能力放行。
- 既有 OCR/TTS/插件不能满足策略时明确阻止并说明原因，不能静默绕过。
- 模型下载是用户显式触发的独立网络动作，不携带待翻译文本；严格模式不是整台应用断网。未来术语链接同步包含术语数据，应单独授权，严格模式暂停同步。
- 前端统一请求上下文，内嵌后端命令执行入口也验证策略；策略切换使在途结果失效并尽可能取消请求，提示已经发出的数据无法撤回。
- 不记录原文、译文、提示词、凭证或含敏感查询参数的 URL。历史记录仍遵循用户开关；关闭历史不等于日志可以记录文本。

## 4. 模型目录与安装任务

### 4.1 目录契约

每个安装单元绑定：模型 ID、不可变 revision、文件路径/字节数/SHA256、语言方向、许可证与署名、运行时 ID/版本、支持的平台和架构、自检样例、测试设备及资源测量条件。

- 首发目录随应用发布，继承应用发布信任链；不要求先建设远程目录服务。未来远程目录必须验证签名、兼容版本与回滚规则。
- 现有模型文件通过校验后复用，不强制重新下载。共享模型由实例引用；删除实例与删除模型是不同操作。
- 版本更新使用新目录，失败保留旧版本。目录与文件路径不得允许越界写入。
- 平台矩阵必须依据当前 ct2rs 构建条件；不支持的目标明确禁用，不向用户承诺 Windows ARM64 可运行。
- M2M-100 要验证分词、语言标记和方向；Hy-MT2 要验证特定量化文件与 runtime commit。依赖未合并实现时不默认分发。
- Piper 后续按语言/音色/质量档列真实大小和许可，校验 ONNX 与配置文件；不把“64 MB / 120 MB”当作通用规格。
- 当前系统语音应按实际探测能力展示；Linux 可能需安装依赖，Windows SAPI 尚不能当作现有实现。

### 4.2 安装状态与恢复

持久化安装任务：`queued → downloading ↔ paused → verifying → warming → ready`，另有 `failed/cancelled`。安装状态与 `unloaded/loading/in_use` 运行状态分离。

任务记录模型/方向/revision、临时目录、文件进度、服务器 validator、失败阶段与恢复点，不存凭证。

- 支持 HTTP Range 时使用 Range + If-Range；正确处理 206、200、416、ETag 变化和镜像切换。不能续传则说明“该文件重新下载”。
- 暂存目录完成全文件校验、自检后原子提交可用版本；只有 ready 的方向可调度。
- 下载暂停/取消会停止读流并释放句柄；取消后是否保留临时文件明确展示。
- 安装、删除、更新按模型加锁；正在使用的资源通过引用管理延后释放。磁盘不足、断网、应用崩溃后不得留下虚假的 ready。
- 预热失败给出错误类型和重试入口；不自动调用云端完成自检。

## 5. 术语与风格

### 5.1 能力分级

| 能力 | 首发支持 | 可承诺的行为 |
|---|---|---|
| source_match | 全部支持纯文本的翻译服务 | 原文命中，不代表译文已采用 |
| output_check | 全部支持纯文本的翻译服务 | 检查固定译法/显式变体是否出现，仅作字面校验 |
| prompt_hint | OpenAI-compatible、Ollama 等已适配服务 | 把命中词条和风格送入提示词，仍可能不遵守 |
| hard_constraint | 首发不提供 | 后续仅经验证的适配器可用，需完整性校验和明确失败状态 |

- Google、OPUS-MT 首发只做原文命中与输出校验，不盲目替换自然语言译文。找不到目标译法不等于翻译一定错误；出现也不等于语义正确。
- 结果区分别显示“原文命中 / 译法已出现 / 未检测到译法 / 冲突 / 不支持约束”，不能把原文命中标为“已锁定”。
- 风格只对能理解指令的适配器开放。术语表仅注入本次实际命中的条目，设置数量和 token 上限，超限时明确提示。
- 术语与原文作为不可信数据隔离；不把用户词条拼成高权限可执行指令，不执行表达式、脚本或远端代码。
- 未来占位符约束必须检查数量、身份、顺序适用性与还原完整性；失败报告约束未满足，不通过拼接目标词伪造成功。

### 5.2 匹配与冲突

- 英文支持词边界，默认大小写不敏感，使用确定的 Unicode 规范化；中文按词组匹配。代码围栏、行内代码、URL、邮箱保留；普通文本中无法可靠识别的变量名不承诺自动识别。
- 最长匹配优先，再按手动覆盖 > 当前领域 > 全局、条目优先级选择；同等级不同译法进入冲突，不注入互斥提示词。
- 明确源/目标语言方向，统一导入语言码与应用内部码（如 zh-CN ↔ zh_cn），不自动反转词条。
- 修改术语或服务配置使请求快照失效；原始翻译缓存可复用，最终校验必须按新术语版本重算。关闭术语恢复原始输出。
- 首发新条目 mode 固定 `suggest`。旧 `locked` 条目保留为约束意图，显示“不支持强制约束”，实际只校验；不得静默降级却显示强制成功。

### 5.3 CSV / JSON 首发规范

- JSON `schemaVersion: 2`，顶层 `id,name,sourceLanguage,targetLanguage,entries`；条目 `id,source,target,mode,caseSensitive,priority,comment`，可选 `tags,targetVariants`。ID 为不透明稳定字符串，编辑时保持。
- CSV 最小必填 `source,target`；可选 `id,mode,case_sensitive,priority,comment`，语言方向在导入向导中必选。无 ID 时本地生成，重新导入先按规范化源词、语言对和匹配规则识别候选重复，由预览确认。
- 支持旧 schemaVersion 1；未知版本拒绝。缺失 mode 默认 suggest；旧 locked 保留意图并提示能力限制；内部匹配策略与布尔 caseSensitive 映射需明确，不能把匹配方式和大小写字段混成同一枚举。
- UTF-8（支持 BOM）、最大 10 MB / 50,000 条；源词/目标词各最多 512 个 Unicode 字符，注释最多 4096 个字符；优先级为 0–1000 的整数，默认 50；CSV 布尔仅接受 true/false（大小写不敏感），JSON 要求布尔类型。错误定位到行/条目；导入先预览，确认后事务提交，失败不改变旧版本。
- 预览显示新增、更新、重复、冲突、错误；支持合并、跳过、整体替换。重复 ID 且内容矛盾需解决，不能以最后一条覆盖。
- CSV 内容作为文本，不执行公式；若提供面向表格软件的导出，需处理公式注入并说明转义与往返规则。
- 示例：[CSV](./examples/glossary-template.csv)、[JSON](./examples/glossary-template.json)、[格式说明](./examples/glossary-import-guide.html)。

### 5.4 后续 TMX 与链接同步契约

- TMX 首先选择“翻译记忆”或“术语候选”，默认预览确认，不默认 locked；首发尚无翻译记忆引擎，因此不提供看似可用的 TMX 按钮。XML 禁用 DTD、外部实体与网络解析，限制深度/大小，指定源目标语言并处理内联标签。
- 远端同步需稳定 library ID、entry ID 和 revision；与上次远端版本做三方合并。远端删除、本地修改冲突进入待确认，不覆盖本地手动条目；区分远端管理条目与本地覆盖层。
- HTTPS、大小/超时限制、ETag/Last-Modified、重定向策略与凭证隔离；默认手动刷新，定时同步需显式开启。失败保留上次成功版本，支持回滚。

## 6. 自定义服务、凭证与迁移

- 用途、协议、名称、Base URL、模型、凭证是统一入口；具体字段由协议决定，不强迫所有 TTS 协议填写 model。
- 首发仅复用 OpenAI-compatible 与 Ollama；正确处理 Base URL 与完整 endpoint，防止重复拼接 `/v1`。支持固定样例试译和取消、超时；不能用模拟成功代替连接测试。
- 非回环地址默认 HTTPS；不跟随携带凭证的跨源重定向。代理策略显式展示，不能宣称一定绕过系统代理；凭证不出现在 URL、错误文本和日志。
- 非敏感配置使用 `secretRef`；Authorization、api-key、token 及秘密请求头都由统一凭证访问层处理。
- macOS Keychain、Windows Credential Manager、Linux Secret Service 分平台适配；后端不可用时默认不持久化秘密，可提供明确提示的会话内凭证，不静默写明文。
- 首发迁移针对本次支持的内置服务及相关秘密；保留旧实例键、名称、排序、启用状态、提示词和线程设置。未适配的插件不能承诺已经安全迁移。
- 迁移流程可重复执行：写入凭证库 → 读回确认 → 原子更新 secretRef 并移除明文。凭证写失败保留原配置并报告待迁移；配置提交失败重试不丢凭证，不自动生成含秘密的迁移备份。
- 备份/导出统一按服务 schema 清理秘密，包括旧键和秘密请求头。无法判定的插件配置默认排除并提示，不能只过滤名为 apiKey 的字段。
- 备份不含实际凭证；恢复时 secretRef 在当前设备不可用则标记“需要重新绑定”，不发送空 Key/错误 Key。旧备份导入同样走迁移和清理流程。
- 审计日志仅保留服务/模型标识、耗时、错误类型；移除现有 resolve 译文日志和可能携带正文的错误输出。测试使用假凭证，不读出真实密钥。

## 7. 数据与兼容实现原则

不一次性替换现有服务配置体系，先添加兼容适配层：

```js
requestContext = {
  id, privacyMode: 'standard', // 或 device_only
  sourceLanguage, targetLanguage,
  serviceConfigRevision, glossaryRevision,
  signal,
};
providerCapabilities = {
  languagePairs: ['en->zh-CN', 'zh-CN->en'],
  execution: 'embedded', // system_offline / external_http / plugin
  streaming: false, // 按真实适配器能力填写
  glossary: { sourceMatch: true, outputCheck: true, promptHint: false, hardConstraint: false },
};
```

- 保留现有服务实例 ID，通过适配层映射 modelRef、能力、凭证引用与显示名称。
- 模型目录、安装记录、运行状态、实例配置、术语库分开存储；多个窗口订阅真实任务事件，状态可重建。
- 把长耗时下载、哈希、推理安排在合适的后台执行器，避免阻塞 UI 或异步执行线程。
- 不支持的平台应编译可用并显示原因；无法在当前机器验证的平台明确列为未验证。

## 8. 实施顺序与交付门槛

以下 A–D 均属于本次首发；E 是明确排除项，不得以“可扩展”名义偷偷加入。
